# AI 模型选择体验优化（70）— 设计文档

- 日期：2026-09-15
- 状态：已实现（2026-09-15，v1.10.1，条目 70；全量单测 582 → 584 全绿）
- 背景：v1.10.0 引入硅基流动后，官方对话模型有数十个，三处体验没跟上：连接成功文案会把全部模型名拼进 snackbar；设置页模型 tab 横滑找模型困难；聊天页不显示当前模型。
- 目标：小步修复（patch 1.10.1），零新增依赖、不动协议与存储。

## 1. 连接成功文案按规模收敛

`connectionMessage`：模型数 ≤ 5 时沿用「连接正常，可用模型：A、B…」；> 5 时改为「连接正常，共 N 个可用模型」，内置模型缺失提醒逻辑不变（`（内置模型与官方不一致，请留意）`）。

## 2. 设置页模型选择：少量用 tab，多量用可搜索弹窗

- 免费填写服务商（自定义）保持模型输入框。
- `availableModels.size <= 8` 沿用 `TextTabRow`（DeepSeek 2 个、硅基未探测时 1 个）。
- 超过 8 个：显示「当前模型 + 选择模型按钮」，点开 `ModelPickerDialog`：
  - 顶部搜索框（按 id 子串、忽略大小写过滤）；
  - `LazyColumn`（高度上限约 320dp）列出模型 id，当前项右侧对勾；
  - 点选即保存并关闭。
- 探测后模型列表持久化行为不变（每个服务商独立）。

## 3. 聊天页显示当前模型

`AiChatViewModel.UiState` 增加 `modelName`（初始化取 `settingsStore.model()`）；聊天页顶栏标题下加副标题 `服务商 · 模型`（`labelSmall`、单行省略；任一为空则省略该段）。会话进行中在设置页切换服务商/模型仍按进入时快照生效（与现行为一致，文档注明）。

## 4. 测试策略

- `connectionMessage`：新增「超过阈值输出计数」用例；原有小列表/缺内置模型用例保持。
- `AiChatViewModelTest`：`state.providerName` 用例补充 `modelName` 断言。
- 弹窗为纯 UI，无既有 UI 测试基建，按项目惯例不新增 UI 测试（编译 + 手工路径在真机验证清单列出）。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 阈值改动影响既有文案断言 | 仅新增用例，既有断言不动（数量 ≤ 5 走原路径） |
| 副标题挤占顶栏高度 | 单行 labelSmall + 省略号；无模型时只显示服务商 |
| 弹窗长列表卡顿 | LazyColumn 惰性渲染；搜索过滤为主路径 |
