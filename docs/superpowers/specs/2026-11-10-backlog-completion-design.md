## 3. 批次 A/B 决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 84 裁剪粒度 | 成对丢弃（assistant + 其后的 user），middle 起点恒为奇数索引 | 逐条丢会让保留列表以 assistant 开头（凭空出现的回答）或出现两条连续 user |
| 84 异常历史 | 裁剪后若不再交替，退化为「首条 + 最新一条」 | 宁可少带上下文，也不给模型错乱序列 |
| 84 既有用例 | 3 个预算用例的历史改为「user/assistant 成对」形态 | 原用例用 3 条（以 user 结尾）的合成历史，编码了逐条丢弃的旧语义 |
| 87 拦截位置 | 包装 LocalUriHandler，而不是改 MarkdownInline 的链接构造 | 一处生效覆盖所有 Text（含引用/表格/列表内的链接），且不污染纯函数解析器 |
| 87 拦截范围 | 只放行 http/https；系统打开异常同样回调而不崩 | file/intent/content/javascript 都可能抛异常或跳到任意 App |
| 90 文案 | 三个纯函数：deleteHint / batchDeleteHint / remainingDays | 两处确认框共用口径，且可单测 |
| 90 恢复/删除反馈 | 回调参数改为「是否真的成功了」 | 笔记在别处被彻底删除时不再假装成功 |
| 92 空查询 | 防抖时长改为按查询词计算（空 = 0ms） | 冷启动首帧不再固定闪 200ms 加载态 |
