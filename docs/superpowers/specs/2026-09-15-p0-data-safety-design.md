- 范围：修复批（递增 patch）；无新增依赖、无 DB 迁移、不改存储结构
- 来源：`docs/backlog.md` 条目 71–76（五域审计批次 E）

## 1. 问题与根因

| # | 现象 | 根因 |
|---|---|---|
| 71 | 插图/导入后重建 Activity，若恰逢启动清理 → 图片被删 → 笔记永久裂图 | `ImageStore.collectGarbage` 是「不在引用集即删」的无保护全扫，而引用集只来自**已提交的 DB 状态**；图片文件先于任何 DB 行落盘（插图写盘 → 草稿稍后才入库；导入写盘 → 事务在最后） |
| 72 | 保留期 30 天改 7 天后，20 天前删的笔记在下次启动被静默永久删除 | 设置页点档位即生效、无确认；清理在冷启动/打开回收站时按新 TTL 物理删除，用户预期只是「以后删除的只留 7 天」 |
| 73 | 新笔记退后台 → 进程被杀 → 回来点保存 → 列表出现两条近似重复笔记 | `_draftId` 只在 VM 里，屏幕侧 `title/content/initialized` 都是 `rememberSaveable`，唯独目标 id 没有；重建后 `isNewNote` 又变回 true |
| 74 | 导入中旋转 → 事务回滚但整包图片已落盘（一条笔记没进来，还占着磁盘）；重导同一备份时同名图片被截断，本地已有笔记开始坏图 | 导入边解压边写正式目录，DB 事务直到最后才开；`writeFile` 直接 `FileOutputStream(dest)`（先截断）+ 无半成品清理 |
| 75 | 两台设备的分类布局不同时，导入直接失败（一条笔记都没进来） | 同 id 分支无条件 `update`，不检查该名字是否已被**另一个 id** 的分类占用，而 `categories.name` 是唯一索引；只有「id 不存在」分支才复用同名分类 |
| 76 | 1000+ 条笔记「全选删除」/ 回收站「清空」崩溃；批量操作失败时界面无反馈 | `IN (:ids)` 由 Room 展开为 N 个绑定参数（API ≤30 的 SQLite 上限 999）；`runBatch`/回收站操作无 try/catch，异常沿 `viewModelScope` 抛出即崩溃 |

## 2. 决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 71 的保护方式 | GC 跳过 `lastModified` 在 `GC_GRACE_MS`（10 分钟）内的文件；顺带清理暂存目录里的过期残留 | 简单、零依赖、可单测；10 分钟覆盖任何一次「插入→保存/导入→提交」的窗口 |
| 74 的导入落盘 | 图片先落 `notes_images_pending/`，**解码成功后、事务之前**提升到 `notes_images/`；提升失败即中止（不留「库里有引用、文件缺失」）；事务失败则回滚提升（被覆盖的旧文件先备份到暂存备份区，回滚时还原）；无论成败清空暂存目录 | 提升失败→DB 未动；事务失败→文件还原。两种失败都不会产生坏引用或孤儿 |
| 74 的单文件写入 | `writeFile` 改「同目录临时文件 → 改名」，失败删临时文件 | 不再截断已有同名文件；`.tmp` 残留会被 GC 按宽限期回收（自愈） |
| 75 的冲突处理 | 先按 id 找、再按名字找：同 id 同名 → 只更新颜色；名字已被占用（含同 id 改名撞名）→ 复用该分类 id 并更新颜色；同 id 改名且名字未被占用 → 直接改名；都没有 → 插入 | 与既有「同名复用」分支口径一致，导入不再因分类布局不同而整体失败 |
| 72 的交互 | 仅在**缩短**保留期且确有超期笔记时弹确认框（显示将立即永久删除的条数），确认后**立即清理并报告条数**；延长则直接生效 | 让「立即删除」的承诺与事实一致，避免把删不掉的状态拖到下次启动 |
| 73 的持久化位置 | 复用编辑页 NavBackStackEntry 的 `SavedStateHandle`（由 `AppNavHost` 显式传入），键 `draft_id`；重建后据此 `observeNote` 并继续更新同一条 | 与 AI 结果回传同一条通道，不引入新存储；`rememberSaveable` 只能存 UI 状态，存不住「已入库的目标 id」 |
| 76 的失败反馈 | 批量/回收站操作加 `onFailed` 回调，界面提示「操作失败，请重试」并**保留选中态**；`getNotesByIds` 按 900 切块、空列表直接返回 | 保留选中态便于重试；切块同时消除 `IN ()` 与变量上限两个隐患 |

## 3. 非目标

- 条目 72 的「缩短后立即清理」不做后台任务：只在设置页确认时同步执行一次。
- 导入的**取消**反馈（旋转中断导入且无提示）属条目 78（批次 F），本批只保证「中途失败不留脏文件/坏引用」。
- 回收站「no-op 也报成功」的文案细化属条目 90（批次 H）；本批只补异常分支的失败提示。
- 不引入 Compose UI 测试依赖；屏幕级行为仍靠可单测的 VM/仓库层覆盖。

## 4. 验收

- 全量单测通过（当前 593 → 新增用例后应更高），`assembleDebug` 通过。
- 关键回归用例：GC 宽限期内不删新文件且过期后照常回收；导入失败不清空/不截断已有同名图片、不留暂存残留；分类改名撞名时导入成功且笔记重映射到正确的分类；1000 个 id 的批量查询不抛异常；草稿目标 id 跨 VM 重建后仍更新同一条笔记；缩短保留期报告并清理超期条数。
