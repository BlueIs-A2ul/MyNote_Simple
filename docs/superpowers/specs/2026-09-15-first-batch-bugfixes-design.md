# 首批缺陷修复（预览崩溃 / AI 流式与上下文 / 保存卡死 / 撤销合并）— 设计文档

- 日期：2026-09-15
- 状态：设计已确认（用户拍板「先修第一批（崩溃 + AI/编辑功能损坏，5 项）」）
- 范围：修复批（递增 patch；无新增依赖、无 DB 迁移、不改存储结构）
- 来源：五域只读审计（数据层 / 编辑页 / AI / 列表导航 / 跨域）+ 主线逐条复核

## 1. 问题与根因

| # | 现象（用户可感知） | 根因 |
|---|---|---|
| 1 | 预览模式下点「图片」插图（或贴 AI 结果、标题按「下一项」）→ **崩溃** | 正文 `BasicTextField`（唯一挂 `contentFocusRequester` 的地方）只在非预览分支组合；三处回调无条件 `requestFocus()`。Compose 1.7.3 的 `FocusRequester` 在无附着节点时抛 `IllegalStateException`（已对 `ui-android-1.7.3/ui-release.aar` 字节码核实：`FocusRequester.class` 含 `not initialized` + `IllegalStateException`） |
| 2 | AI 流式回答只显示最后一两个字；点「停止」/看门狗超时/中途退出后，落库的半截回答只剩最后一片 | `AiSseParser` 取 `delta.content`（增量），`AiApiClient` 逐片发 `Chunk`，但 `AiChatViewModel` 用**赋值**而非追加（同文件的 `Reasoning` 分支是追加） |
| 3 | 追问时模型「忘了」笔记内容 | `AiApiMessageBuilder` 以「历史里是否已有 user 消息」决定是否附带正文，而 `AiChatViewModel` 落库的是**裸输入**（不是包好正文的那条）→ 第 2 轮起正文不再发送 |
| 4 | 「保存」可能永久变灰，之后的编辑全部静默丢失（退后台兜底也失效） | VM 的 `save()` 与 `saveDraft()` 共用同一个 `saving` 标志；屏幕侧 `isSaving` 只在 `vm.save` 的回调里复位。ON_STOP 草稿写入期间点「保存」→ 提前 return → 回调不执行 → `isSaving` 永久 true，而 ON_STOP 兜底被同一标志 gate |
| 5 | 连打一段文字后按「撤销」只回退 1 个字符，然后再也撤不回去（比合并前更差） | `NoteUndoController.record()` 合并时 `removeLast()` 再 `addLast(before)`，用「最后一次编辑前」替换栈顶，**整段起点被丢弃**；类注释与测试名却声明「一次撤销回退一整段」，测试断言把错误语义固化了 |

## 2. 决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 预览模式焦点 | 新增纯 Kotlin 小状态机 `BodyFocusGate`：预览中只登记 pending，回到编辑态再补一次聚焦 | 既消除崩溃，又保留「贴入结果/插图后光标就位」的既有体验；纯函数便于单测（本仓库无 Compose UI 测试基础设施，且不得新增依赖） |
| `Chunk` 契约 | 明确为**增量**，只在 VM 侧追加；测试统一改为增量语义 | 与协议实现（`delta.content`）和 `AiSession` 接口注释一致；`Done` 仍带全文，最终回答不受影响 |
| 笔记正文携带方式 | **请求时**保证首条 user 含正文（幂等重包），落库仍存裸输入 | 聊天记录展示不变、历史数据无需迁移；对老会话同样生效（其首条也是裸文本） |
| 保存标志 | VM 拆分为 `saveJob` / `draftJob`：`save()` 先 `join()` 在途草稿，`saveDraft()` 在正式保存进行中直接跳过 | 既保证回调必定执行（修 UI 卡死），又避免「草稿插入未落库就正式保存」导致重复插入 |
| 撤销合并 | 合并时**不动栈顶**（保留整段起点），另用 `lastBefore` 做邻接判定；`undo()/redo()/reset()` 清空 `lastBefore` | 与既有注释/测试名声明的语义一致；清空 `lastBefore` 防止撤销后继续输入被错误合并而丢格 |

## 3. 非目标

- 审计中其余条目（图片 GC 误删、保留期静默删除、draftId 未持久化、Key 进 Bundle、导出/导入作用域、导入分类冲突、搜索通配符、硬编码 30 天、多选残留、冷启动闪加载、AI 身份一致性、看门狗不停流、空回答落库、`http://` 明文、链接 scheme、无障碍等）留待后续批次。
- 不引入 Compose UI 测试依赖（违反「零新增第三方依赖」硬约束）；屏幕级行为用可单测的纯函数/小状态机覆盖。

## 4. 验收

- 全量单测通过；新增用例覆盖：预览态焦点门控、增量分片拼接（含停止后落库）、第二轮仍带正文、草稿在途时保存不被拦截、撤销合并保留整段起点与撤销后新编辑新开一格。
- 无用户可感知的行为回退：`Done` 全量文本路径不变；首轮请求体与修复前一致。
